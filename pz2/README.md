## Описание проекта
Интерактивное 2D-приложение на PyGame, моделирующее процесс посещения пекарни. Пользователь управляет клиентом, перемещается по помещению, оформляет заказ через графическое меню, ожидает приготовления и забирает заказ в зоне выдачи.

## Что реализовано

### 1. Окно приложения и игровой цикл
- Окно размером 1000×650 пикселей
- Частота кадров 60 FPS
- Корректное завершение по Esc или закрытию окна
- Основной цикл с обработкой событий, обновлением логики и отрисовкой

### 2. План пекарни
- 4 зоны: вход (синий), прилавок (коричневый), касса (серый), зона выдачи (зелёная)
- Визуальные подписи зон
- Прилавок и касса — препятствия для клиента

### 3. Управление клиентом
- Клиент представлен кругом (радиус 20 пикселей)
- Управление WASD (вверх/влево/вниз/вправо)
- Непрерывное движение при удержании клавиш
- Поддержка диагонального движения
- Скорость 200 пикселей в секунду
- **Delta time** — движение не зависит от FPS
- **Нормализация диагонали** — скорость по диагонали не выше, чем по прямой
- **Коллизии** — клиент не проходит через прилавок, кассу и границы окна

### 4. Смена цвета
- По нажатию SPACE цвет клиента циклически меняется
- 4 цвета: красный, зелёный, синий, оранжевый
- Смена происходит один раз на нажатие (не при удержании)

### 5. Взаимодействие с прилавком
- Жёлтая полупрозрачная зона перед прилавком
- Подсказка "E — сделать заказ" появляется, когда клиент в зоне
- Нажатие E вне зоны не открывает меню

### 6. Меню заказа
- Графическое меню с 4 товарами:
  - Хлеб — 70₽ (остаток: 3, без приготовления)
  - Булочка — 90₽ (остаток: 4, без приготовления)
  - Сэндвич — 180₽ (остаток: 2, приготовление 5 сек)
  - Кофе — 140₽ (остаток: 5, приготовление 3 сек)
- Выбор товара клавишами 1–4
- Закрытие меню по ESC без покупки
- Товары хранятся в списке словарей

### 7. Деньги и остатки
- Начальный бюджет: 420₽
- Проверка наличия товара перед заказом
- Проверка достаточности средств
- Сообщения: "Заказ принят", "Недостаточно денег", "Товар закончился"
- При успешном заказе: вычитание стоимости, уменьшение остатка
- Текущий баланс отображается постоянно

### 8. Состояния заказа
Конечный автомат с 4 состояниями:
- **NO_ORDER** — заказа нет
- **WAITING** — товар готовится (сэндвич, кофе)
- **READY** — заказ готов к получению
- **DONE** — клиент забрал заказ
- Одновременно только один активный заказ

### 9. Приготовление без time.sleep()
- Обратный отсчёт на основе delta time
- Приложение остаётся отзывчивым во время ожидания
- Клиент может свободно перемещаться
- Автоматический переход в READY по истечении времени

### 10. Индикатор прогресса
- Графическая полоса заполнения (progress bar)
- Название готовящегося товара
- Оставшееся время в секундах
- Визуализация: зелёная полоса растёт по мере приготовления
- Сообщение "Заказ готов!" при завершении

### 11. Получение заказа
- Зона выдачи меняет цвет на светло-зелёный, когда заказ READY
- Подсказка "E — получить заказ" появляется в зоне
- Нажатие E переводит состояние в DONE
- Сообщение "Заказ получен!"
- Возможность оформить новый заказ

### 12. Информационная панель
Постоянно отображается в левом верхнем углу:
- Money: текущий бюджет
- Order: название текущего заказа
- State: состояние заказа
- FPS: текущая частота кадров
- Всплывающие сообщения об ошибках и событиях

### 13. Организация кода
Программа разделена на функции:
- `main()` — основной цикл
- `handle_events()` — обработка ввода
- `handle_movement(dt)` — движение клиента
- `update_order(dt)` — обновление состояния заказа
- `draw_scene()` — отрисовка пекарни
- `draw_ui()` — отрисовка интерфейса
- `draw_menu()` — отрисовка меню
- `draw_progress_bar()` — отрисовка индикатора
- `check_collision()` — проверка столкновений
